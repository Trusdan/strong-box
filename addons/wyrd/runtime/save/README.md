# save

`WyrdSave.capture` / `apply` implement `WyrdRuntime.save_state` and `load_state`.

Schema version is 4. `WyrdSave.migrations` has three steps. The first fills `facts.believed` and `facts.held` when a schema 1 save is missing them. The second leaves the document unchanged. The third adds an empty `generator` object when the key is missing. That step does not write `schema_version` and does not change `quests`, so `_import_flight` still sees the file's own version against `FLIGHT_SINCE_SCHEMA` (3). A schema 2 save has no `flight` key. It loads with empty token queues and a zero slice, and the dirty waits stay armed, the same result as a schema 2 load. A schema 3 save omits `flight` only when the rumor queue, the publish queue, the token queues, the slice, and the dirty waits are all empty. That load clears the dirty waits too. A version below 1, or a version this table cannot reach, is `E_SAVE_VERSION`. Schema 5 is refused with that same message. Load content first. A save that lists content packs while none is loaded is `E_CONTENT_MISSING`, and the message names those pack ids. A save with no pack ids in that case stays `E_SAVE_VERSION` (`load content before loading a save`). Register rumor policies before loading a save that still has a mutation chain. The callables are not in the file. Load rebinds them from the policy id. A job or a reach row whose policy id is not registered adds `error[E_SAVE_POLICY]` and `push_error`. Both name the policy id and the deed. That deed's jobs, rumor tokens, reach rows, seen and queued sets, once-set, and copies are left out. Other rumors load. A belief already written stays. The load still applies.

`load_state` checks a deep copy before it changes the runtime. The check runs migrations on that copy, then the seed, the pack hash, every RNG stream (the `WyrdRng` objects are built here), and `check_shape`. A present field of the wrong type is `E_SAVE_VERSION` and names the key path (`save field quests.ferry_toll.outcomes must be a dictionary`). A missing key is left alone. A whole-number float counts as an int. The `ai` key is not shape-checked: a malformed cache still warns `W_SAVE_AI` and the load continues. Nothing is cleared or imported until the check passes. The import cannot refuse. `E_SAVE_POLICY` still names a dropped in-flight rumor, adds a `policy` row, and leaves `ok` true.

`WyrdSaveMigrate.apply_aliases` runs after `check_shape` passes, on the working copy. It is pure and static. Empty alias tables return that copy unchanged and add no rows. It rewrites a quest row's top-level `stage` and each `trail` entry (the table scope is the row's `template` when that field is set, otherwise the text before `#` in a generated id such as `ferry_job#3`, otherwise the quest id), role-id keys of `roles.bindings`, `roles.defs`, `roles.told`, and `roles.pending`, entries of `roles.abolished`, the `verb` of each `deeds.rows` entry and of each in-flight `flight.rumor.jobs` and `flight.rumor.reach` row, the `doc` of each `documents.read` and `documents.copies` row, and a periodic document's publish state: keys of `flight.publish.counters` and `flight.publish.covered`, the document part of each `flight.publish.queued` entry (`<doc>\t<due>`), and the document field of `flight.publish.cursor` and of each `flight.scheduler.publish` token (`issue\t<doc>\t<n>\t<due>`). After a trail is mapped, a repeated id keeps its last position. Region leaves, `roles.frozen`, the generator block, facts (including `skip <doc>#<n> due=<minute>` and `role.<id>.holder`), and journals stay as saved. A document's publish state moves as one unit. When an old role key or abolished entry, a `(reader, doc)` read, a `(doc, copy)` pair, or any publish state of the new document id is already saved, the new id's data stays and every old entry is dropped (counters, covered minutes, queued dues, scheduled tokens, and the cursor with its `beliefs` and `claim`). That drop warns `W_SAVE_ALIAS` (`saved <kind> "<old>" was dropped because "<new>" is also saved`) and the load stays `ok`. Each rewritten subject adds an `alias` row: `from` is the old id, `to` is the final id, `code` is empty, and `count` is how many entries were rewritten (one for a stage, one per rewritten trail entry). `id` is `stage:<quest row id>`, `trail:<quest row id>:<old>`, `role:<old>`, `document:<old>`, or `verb:<old>`. Publish and rumor rewrites add to that document's or verb's existing row. A drop adds a second `alias` row for that same id with `code` `W_SAVE_ALIAS` and `count` the number dropped. A merged trail duplicate is not a collision. A refused load never reaches the pass, so it still has only its `refused` row. A clean load, and any load into content without aliases, still has no `alias` rows. A document id or role id the pass rewrote to a declared id is not a `kept` row.

`WyrdSaveMigrate.resolve_stages` is the next step, on that rewritten copy. It is pure and static and reads only quest and template definitions. A quest row whose `stage` is no longer a top-level stage of that quest (or of its template, for a generated row) moves to `on_missing_stage` when that stage exists, else the last `trail` entry that is still a stage, else the first declared stage. The row arrives entered: `variant` is empty, `step_at` counts the base body's journal lines, effects, scenes, and host steps, `offered`, `waiting`, and `host_screen` are empty, `scene_done` and `held_empty` are false, `host_fields` is empty, and `regions` are the base body's initial leaves, each entered with its own entry steps counted. `status`, `outcomes`, `slots`, `host_returns`, and `journal` stay. The new stage is appended to `trail` (distinct, newest last, at most 32). Nothing runs: no entry effects, no journal line, no slot lock, no trace. A saved region leaf that the current body no longer has restarts at that region's first stage the same way, including nested leaves; the report id is `<quest row id>/<region path>`. Regions the body does not declare stay as saved. Each move adds a `missing_stage` row (`from` the old id, `to` the new id, `count` 1, `code` `W_SAVE_STAGE`) and one warning `W_SAVE_STAGE` (`saved stage "<old>" of "<id>" is gone; moved to "<new>"`). The load stays `ok`. A second run adds no rows. An empty `stage`, and a quest or template the content does not declare, are left untouched.

`WyrdLoadReport.rows` is a sorted list of `{kind, id, from, to, count, code}`. A clean load has none. `load_content` leaves `rows` empty. `load_state` adds one row per diagnostic: `refused`, `manifest` (save hash in `from`, content hash in `to`, 16 hex digits), `template`, `ai`, and `policy` (the deed id). It also adds `kept` for a saved id the pack does not declare and the runtime keeps: storylet, sequence, topic, document, hand-written quest, and role, with `from` naming that store and `count` 1. A role counts when it is in the imported roles block and neither the content nor a host `define()` since the last content load has it. Bark speaker clocks have no content id list, so they are not `kept` rows. A removed hand-written quest is written back unchanged and is not ticked. An instance whose template is missing keeps its `template` row and is not a `kept` row. `load_report_ready(report)` fires once at the end of every `load_state`, on the runtime and on the facade, including a refusal. Loading adds no trace line.


`ai`, when `WyrdConfig.ai_save_cache` is true and the cache is not empty, holds `v` (`1`) and `cache`, an array of `{k, t}` oldest first. `k` is 16 lowercase hex digits. `t` is the validated text. The key is omitted when the cache is empty or `ai_save_cache` is false. Schema stays 4. An older loader ignores the key. Open requests are never saved. A missing key clears the cache. A key that is not a dictionary, whose `v` is not 1, or whose `cache` is not an array, warns `W_SAVE_AI` ("AI cache is not valid and was ignored"), clears the cache, and the load still succeeds. Rows that are not dictionaries, whose `k` is not 16 lowercase hex digits, or whose `t` fails the saved-text check are skipped; one `W_SAVE_AI` warning names the count ("AI cache: <n> entries were not valid and were skipped") and the valid rows load. `ai_save_cache` does not affect loading. The cap is `ai_cache_max` at load time.

`generator`, when any instance counter exists, holds `counters` (template id to the last `n`) and `instances` (`<template>#<n>` to `{casts: {slot: {holder, status}}}`, plus `owner` on an item cast). The block is omitted when there are no counters. A generated quest row adds `template` and `n`. Hand-written rows do not, and their frozen casts stay in `roles.frozen`. Instance casts are not written there. A save whose template is no longer in the content keeps that template's rows, instance entries, and counters, and writes them back unchanged. Load warns once per missing template, `W_SAVE_TEMPLATE`, with `load_missing kind=template id=<template> instances=<k>`. `report.ok` stays true. Those instances are not restored and do not tick.

`documents`, when any read flag or frozen copy exists, holds `read` (rows of `doc` and `reader`, sorted by reader then doc) and `copies` (rows of `copy`, `doc`, and `record`, sorted by doc then copy). The bag is omitted when both lists are empty. A missing key clears both. Unknown document ids and readers are kept and ignored. Read flags in that bag are not stored facts: they are not in `facts`, and load does not log `document_open`, `document_copy`, or `document_stale`. There is no migration step for the bag.

The document holds pack id and manifest hash, language version, world, known, believed, and held facts, the deed log, relationship baselines and kinds, role bindings, definitions, frozen casts, and told sets, quest status, stage, an optional `trail` of top-level stages entered (distinct, most recent last, at most 32, omitted when empty), outcomes, slots, host-step fields, frozen journal rows, and region leaves when a stage has them, effect provenance, play minutes, the game seed, and each named RNG stream's `to_state()`. `sequences`, when present, holds partial or finished sequence rows (`count`, `done`, and `started` or `matched` when set). A missing `sequences` key clears that bag only. An unknown sequence id is kept. Believed and held bags are sparse: an agent or group appears only when it has keys. `storylets`, when present, holds line-set draw rows and director `seen` / `last_minute`. `bark_speakers`, when present, holds bark speaker clocks (`cooldown` and `last_minute`). A missing `bark_speakers` key clears those clocks and leaves storylet rows. `why-not` reads those bags and does not add a key. The unlocked secrecy name is an ordinary world fact. Schema stays 2 and the save has no secrecy key. `WyrdConfig.secrecy_tiers`, `WyrdConfig.secrecy_fact`, and `WyrdConfig.trace_director` are host knobs and are not saved. An id the pack does not declare is kept and ignored. An unknown speaker id is kept.

`flight`, when any in-flight state exists, holds `rumor`, `publish`, and `scheduler`. Empty sections are omitted. The whole key is omitted when all three are empty. `rumor` holds `jobs` (chance, deed, key, kinds, max hops, policy id, claim value, verb), `seen` and `queued` (deed plus sorted who), `reach` (born, deed, key, level, pending, place, policy id, claim value, verb), `drawn` (`deed`, who), `held` (deed, value, who), and `gone` (deed, who). Mutation callables are not stored. `publish` holds `counters`, `covered`, and `queued` dues (`doc`, due). An open issue also stores `cursor`, the issue token, plus `beliefs` (the member snapshot from the first slice, rows of `deed`, `t`, and `who`) and `claim` (`source` and `value`). The gathered rows are not saved. Load keeps that snapshot and continues the issue. A save with `cursor` and no `beliefs` starts that issue over. A save with no open issue omits `cursor`. `scheduler` holds `rumor`, `publish`, and `cache_refresh` tokens in order, `waits` (sorted dirty condition indexes), and `slice` (leftover units, omitted at 0). A `StringName` claim is `{"t": "symbol", "v": "..."}`. A float claim is `{"t": "float", "v": n}`. Bool, int, string, and null stay JSON values. Load does not log `rumor_hop`, `rumor_adopt`, `rumor_reach`, `rumor_materialize`, or `rumor_mutate`.

A frozen issue, and a `skip <id>#<n> due=<minute>` line, stay in `facts` because those writes are ordinary world facts. The counter and the covered minute are restored with the queued dues, so a loaded issue is not numbered again and a skipped due is not published later. Load does not log `publish` or `publish_cursor`. Cache entries, the deed index, and the storylet index are not save keys. `cache_refresh` tokens ride in `flight.scheduler`.

The rumor believer index is not its own save key. Each deed row in the `deeds` bag may carry `believers`, a list of `{t, who}` sorted by who. `t` is the adoption minute. Load rebuilds the index from those fields. `believed/` values do not name a deed or an adoption minute, so they are not enough to rebuild it. A save written before the field has the belief text and no deed link. Compaction rewrites the same bag: listeners from a merged group move onto the newest id, the earlier minute wins, and a dropped row takes its listeners with it.

The inspector snapshot is not a save key. Load does not log `debug_snapshot`. Deed compaction removes provenance rows whose facts are not marked `recap`. That still uses the `provenance` key. Load does not log `choice_summary`. Coverage counts are not a save key. Load does not log `coverage`. A console `set` stores provenance with scene `console` and choice `set` on the existing `provenance` key. Load does not log `console`. 64-bit values are lowercase hex so `JSON.stringify` does not round them. Other integers are coerced back to int on load. A scene must be closed. A hash mismatch adds `W_SAVE_MANIFEST` when `OS.is_debug_build()` is true and stays silent in a release. The load still applies.
