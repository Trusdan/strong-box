# publish

`WyrdPublish` builds periodic document issues on the scheduler's `publish` queue.

A periodic `document` block names a group, a period, and a delay. A readable document has no `publishes_by`, `every`, or `delay`, and its `period_minutes` stays 0, so this queue skips it. Units are `minute` or `minutes` (1 game minute), `hour` or `hours` (60), and `day` or `days` (1440). The first issue is due at `delay` game minutes after a new game. The next is due one period later. `tick(0)` before that delay publishes nothing.

`deeds_known_to(group, since, filter)` returns deed rows that any current member of the group witnessed, or believes through a rumor, at a qualifying minute `>= since`. Membership is `WyrdWorldAdapter.members`. The witness index is the knower list from the deed log. A witness uses the deed minute. `saw` is `known`. `heard` and `inferred` are `believed`. A rumor listener uses the believer index and the minute they adopted the claim. That listener is `believed` even when they are not a witness. A plain `believed/` write does not add a deed. An empty filter keeps every verb. Any other filter is the verb. Rows are unique by deed id and sorted by that id. `t` on the returned row is the earliest qualifying witness minute or adoption minute, and that is the minute the issue window uses. The same person is listed once. A `saw` witness stays `known` when they also believe the rumor.

One publish unit is one frozen issue. The token is `issue`, the document id, the issue number, and the due minute. The handler ignores any other token. The issue number starts at 1. The copy id is `<id>#<n>`. The deed window is `[due - period, due)`. The copy is built when the unit runs, not when it is queued.

The issue claim is chosen in this order. The first fragment whose `when` is true supplies its `slant` symbol. Otherwise the `believed/<member>` value of the lowest sorted current member wins, including a value a rumor mutation wrote. Otherwise `known/<member>` of the lowest sorted member. Otherwise the world fact. The deed row is not rewritten. There is no roll. The same deeds, membership, and facts produce the same line.

After a jump, one visit enqueues at most `WyrdConfig.publish_catchup_max` missed issues per document, oldest first. The default is 3. `0` or a negative value enqueues none. Every missed due is numbered, including the ones past the cap. Those extra issues are written immediately as `skip <id>#<n> due=<minute>` in the document fact. They are not publish tokens and they do not log `wyrd publish`. A later visit, including one after save and load, does not publish that due and does not reuse that number. The cap is not a time budget. The queue still spends `scheduler_share_publish` work units.

The frozen line, and each skip line, is appended to the document's `fact` symbol. That write is an ordinary world fact. A published line starts with the copy id. A skip line starts with `skip` and then the copy id. On the next visit the highest `#n` in that text is the last number, and a due minute already in the text is not published again. The in-memory counter, the covered minute, and the queued dues are saved in `flight.publish`. The issue tokens are saved in `flight.scheduler`. A schema 2 save has no `flight` key, so a due that was only queued can be published again and its number is the next one past every `#n` already in the fact. A due that was written as a skip line stays skipped.

With tracing on, a built issue logs `wyrd publish document=<id> issue=<id>#<n> deeds=<count>`. `path` is the document id, `key` is the copy id, and `who` is the group. Replay skips the line. Load does not log it.
