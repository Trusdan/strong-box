# scheduler

`WyrdScheduler` runs the fixed-work queues: waits, rumor, publish, cache refresh, generate, and AI pre-fetch. `WyrdTickQueue` is the waits list. One unit is one waiting-condition recheck, one rumor hop or one coarse reach rise, one frozen issue, one cache rebuild, one generate offer, or one AI pre-fetch visit.

`Wyrd.tick(game_minutes)` accepts any non-negative slice, including a fraction. Slices accumulate. A whole game tick runs only when `scheduler_tick_minutes` (default 1) have accumulated. The clock advances by those whole ticks. A call with `0` still runs one game tick and does not move the clock, so existing flush sites stay valid. Slices quantize to 1/720 of a game minute, which makes a 30 fps slice and a 144 fps slice of one game minute add up exactly.

Each game tick spends at most `scheduler_work_per_tick` units. The six share weights split that budget. `scheduler_share_generate` and `scheduler_share_ai_prefetch` default to 0. Round-robin gives each queue one unit at a time, up to its share. Unused share moves to the earliest queue that still has work, so waits still receives the full budget while the other queues are empty. Generate has work only when a handler is set and an offer is waiting. AI pre-fetch has work only when AI is active and a bark sweep still has storylets. With a zero weight, `apportion` gives that queue a floor of 0 and a fraction of 0. The remainder goes only to a strictly larger fraction, so a zero sixth weight leaves the first five shares exactly as they were with five queues. Spill reaches AI pre-fetch only when queues 0–4 are all idle, and one of its units does not create work for an earlier queue. Both default-zero queues therefore run only by spill onto an otherwise idle tick. Neither keeps tokens, and neither is saved. `flight.scheduler` still holds the four token queues, the dirty waits, and the leftover slice. `run` still reports `spent` and `carry` for those four, plus `generate_spent`, `generate_carry`, `ai_prefetch_spent`, and `ai_prefetch_carry`. Unfinished items stay in order. A schema 2 save loads with empty token queues and a zero slice, and leaves the dirty waits armed. A schema 3 save that omits `flight` had an empty dirty set, so that load clears it. Load does not log `wyrd scheduler`.

A debug build can log `wyrd scheduler queue=frame` when the units take longer than `scheduler_frame_warn_usec` (default 2000 microseconds, 2 ms). `0` disables it. That line is information only. The trace row sets `timing` true. `WyrdTrace.diff` leaves it out.

The rumor queue delivers one precise hop, or one coarse reach rise, per token. Coarse rises use the same share and the same work budget. See `runtime/rumor/README.md`.

The publish queue delivers one frozen issue per token. A visit enqueues at most `publish_catchup_max` missed issues per document (default 3). Issues past that cap are numbered in the document fact and are not published later. That cap is a count of issues, not a time budget. See `runtime/publish/README.md`.
