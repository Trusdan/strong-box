# trace

`WyrdTrace` is optional. Set `enabled` before the calls you want to record. `start_new_game` clears `events` and leaves `enabled` as it was.

Inputs, which `replay` runs again: `open_scene`, `advance`, `choose`, `abort`, `tick`, `emit`, `complete_host`, `draw`, `open_document`, `create_copy`, `ai_deliver`, `quest_summary`, `ai_host_request`, `gen_offer` (host origin), `gen_propose`, `gen_accept` (host origin), and `host_call`. A `host_call` row is one direct game call. `call` is `<object>.<method>` and `args` is the full positional argument list, defaults included. It is logged only when no other Wyrd call is already in progress on that runtime, and it is logged before any row the call itself logs. The prefix filter does not drop it. A call that changes no stored state and logs no compared row is skipped. `director.query` is always recorded. A call Wyrd makes inside its own work is not recorded, because replay runs that work again. A trace with no `host_call` rows replays as before, and the host repeats those calls itself. A `gen_offer` row is replayed only when `origin` is `host`. A `gen_accept` row is replayed only when `origin` is not `queue`. A `gen_accept` row with no `origin` is a host row and is replayed. A `queue` row stays in the trace and `diff` still compares it. Emit, proposal and AI request ids restart after a load, so a replay that crosses a load sees restarted ids and a split run is compared with its own recording, not with an uninterrupted one. `ai_deliver` builds a `WyrdAIResult` from `id`, `ok`, `text`, and `error` and calls `Wyrd.ai.deliver`. It is recorded and not printed. A provider that answers inside its own `request` call records that row during the input that sent it, so replay delivers the row only after that input returns. Lines shown during that same input can then differ. A provider that answers on a later frame replays the same text. `quest_summary` calls `Wyrd.quests.summary`. `ai_host_request` calls `Wyrd.ai.request`; the request kind is stored as `slot_kind`, because `kind` is the event name. With those rows a replay sends the same requests with the same ids, so each recorded `ai_deliver` answers the right request. Before they were inputs, a host `request` shifted later ids in a replay. `ai_prefetch`, `ai_use`, `ai_late`, and `ai_sweep` are skipped, like the other `ai_*` rows. An `ai_sweep` line is one bark sweep armed (`reason` `start`, `change`, or `floor`) or dropped (`off`, `provider`, `new_game`, or `load`).

`topic_unlock`, `topic_lock`, `quest_start`, `quest_advance`, `role_assign`, `role_vacate`, `baseline_adjust`, and a host `ai_cancel` stay decision rows. The `host_call` row regenerates them. Host answers and decisions, which `replay` skips and `diff` compares: `line`, `line_audio`, `choices`, `resolver`, `command`, `skill_check`, `transition`, `roll`, `host_step`, `director`, `director_candidate`, `why_not`, `region`, `sequence`, `voice`, `secrecy`, `debug_snapshot`, `choice_summary`, `choice_compact`, `coverage`, `coverage_report`, `console`. A `director` line is one query: scope, speaker, candidate count, winner, and score. A `director_candidate` line is one scope-and-speaker match, logged only when `WyrdConfig.trace_director` is true and tracing is on: `wyrd director_candidate scope=%s speaker=%s storylet=%s score=%s eligible=%s clause="%s"`. `path` is the storylet id. `key` is the scope id. Load does not log one. A `why_not` line explains one storylet: eligible, reason, failing clause, score, cooldown, remaining, and winner. The prefix filter also matches `scope`, `speaker`, and `path`. `key` on a director or why_not line is the scope id. A `region` line is one leaf change: `wyrd region quest=%s path=%s from=%s to=%s`. `path` is the region id, or parent ids joined by `/`. An empty `from` is the first leaf. The prefix matches `quest` or `path`. A `sequence` line is one step, finish, reset, or expiry: `wyrd sequence id=%s count=%s done=%s reason=%s`. `reason` is `step`, `done`, `reset`, or `expire`. `key` on that line is the sequence id. A `voice` line is one holder-variant pick: `wyrd voice line=%s holder=%s chosen=%s`. `key` is the name-free line id. `who` is the holder, empty when the slot or role is vacant. The pick is display-time and is not saved. A `secrecy` line is one dropped storylet or line: `wyrd secrecy storylet=%s line=%s tier=%s unlocked=%s`. `key` is the storylet id, or the line id when the drop has no storylet. `path` is the line id. An allowed name is not logged. Load does not log one. A `debug_snapshot` line is one inspector read: `wyrd debug snapshot sections=%s prefix=%s offset=%d limit=%d rows=%d`. `key` is the caller prefix. `path` is the section list, or `*` when every section was requested. The prefix matches `key` or the start of `path`. Load does not log one. Replay skips it. A `choice_summary` line is one provenance read: `wyrd choice_summary scene=%s choice=%s prefix=%s from=%s to=%s rows=%d`. `key` is the key prefix. `path` is the scene filter. An omitted filter prints `-`. A `choice_compact` line is one provenance drop during deed compaction: `wyrd choice_summary compact kept=%d dropped=%d`. `path` is the dropped keys joined by commas. The prefix matches the start of that list. Load does not log either line. Replay skips both. A `coverage` line is one recorded hit: `wyrd coverage kind=%s id=%s count=%d path=%s line=%d`. `hit` is `storylet`, `line`, or `variant`. `key` is the id. `path` is the source file, or empty when the id is not in the catalog. An empty path prints `-`. A `coverage_report` line is one never-hit read: `wyrd coverage report missed=%d`. `key` and `path` are empty, so a prefix filter drops it. Load does not log either line. Replay skips both. A `console` line is one playtest command: `wyrd console command=%s key=%s role=%s source=console ok=%s`. `path` is `console`. `key` is the fact, role, event, scene, or minute text. `role` is set for kill, vacate, and replace. An empty key or role prints `-`. The prefix matches `path`, `key`, or `role`. `quit` and a blank line are not commands. Load does not log one. Replay skips it. A `rumor_hop` line is one precise offer: `wyrd rumor hop deed=%s policy=%s from=%s to=%s hop=%d key=%s taken=%s reason=%s`. `reason` is `pass`, `chance`, or `coarse`. `path` is the policy id. `who` is the listener. A `rumor_adopt` line is the credibility check for an offered hop: `wyrd rumor adopt listener=%s speaker=%s policy=%s key=%s score=%s accepted=%s`. A `rumor_reach` line is one coarse rise: `wyrd rumor reach deed=%s place=%s policy=%s level=%d key=%s`. `who` is the place. A `rumor_materialize` line is one seeded draw: `wyrd rumor materialize listener=%s place=%s policy=%s key=%s level=%d chance=%s accepted=%s`. A `rumor_mutate` line is one field on an accepted hop or materialize: `wyrd rumor mutate listener=%s speaker=%s policy=%s field=%s hop=%d kept=%s result=%s value=%s`. `who` is the listener. `path` is the policy id. Replay skips all five. Load does not log them. A `publish` line is one frozen issue: `wyrd publish document=%s issue=%s deeds=%d`. `path` is the document id. `key` is the copy id. `who` is the group. Replay skips it. Load does not log it. A `document_open` line is one open of a readable document: `wyrd document_open document=%s copy=%s reader=%s first=%s ok=%s reason=%s`. `reason` is `opened`, `periodic`, `secrecy`, or `no_copy`. `key` is the document. `path` is the copy. `who` is the reader. An unknown document or reader is `push_error` and logs no line. A `document_copy` line is one copy: `wyrd document_copy document=%s copy=%s source=%s ok=%s reason=%s`. `source` is `content` or `host`. `reason` is `created`, `already`, `live`, `periodic`, or `params`. `key` is the document and `path` is the copy. A repeat traces `already` and does not warn. A `document_stale` line is one frozen paragraph whose record does not match the compiled walk: `wyrd document_stale document=%s copy=%s line=%s`. `key` is the document and `path` is the copy. Replay inputs are `open_document` and `create_copy` for host calls. Effect-created copies replay through the effects. Replay skips the three printed lines. Load logs none of them. A `skill_check` line is one host answer: `wyrd skill_check scene=%s choice=%s skill=%s roll=%s ok=%s reason=%s`. `key` is the skill. `path` is the scene id. `reason` is the host reason, `no_adapter`, or `-` when empty. `roll` is the seeded unit in `[0, 1)`. Replay skips the row and asks the host again from the recorded `choose`. Load does not log it.

Field keys are sorted, then `kind` is inserted first, so a JSON dump is stable. A row with `timing` true is a wall-clock diagnostic: the scheduler frame warning sets it, because `us` and the row's presence depend on measured time. `diff` leaves those rows out and compares every other row exactly. The row stays in the trace. `diff` reports up to eight mismatches. A host that answers differently (a command that fails, a resolver that changes) produces a non-empty diff. Replay does not inject host answers. The second runtime must be booted the same way, then given the recorded inputs.
