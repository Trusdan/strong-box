# roles

`WyrdRoles` keeps one binding per role: `holder`, `since`, `status` (`default`, `successor`, `empty`, `contested`), and `history`. `contested` is the open `election` or `host_decides` request.

A role definition comes from a `role <id>` block or from `define()`. Both store `scope`, `eligibility`, `default_holder`, `visibility`, `succession`, and `vacancy`. See `docs/language.md#role`.

`eligible(role, entity)` runs the eligibility condition with `candidate` bound to that entity. No condition means every entity passes. When a condition is present, the trace bus gets one `eligible` line (`role`, `entity`, `ok`) and, if tracing is on, the console prints `wyrd eligible role=<id> entity=<id> ok=<bool>`. The line does not grow with the facts the condition reads.

`assign` sets the holder. A `default_holder` is assigned when the binding is empty, including on a new game. `assign` refuses an abolished role, and it refuses the departed holder while a contest is open.

`vacate` tries one strategy. `relation(kind|kind)` walks outgoing kinds on the departed holder and takes the first living eligible entity with a different id. `faction_assigns(faction)` reads `WyrdWorldAdapter.members(faction)`, keeps living eligible members other than the departed holder, and orders them by `set_faction_rank` (higher int wins). Equal ranks use `WyrdRng.for_decision` on the game seed, the role, the faction, the departed holder, and the current minute. `host_decides` and `election` clear the holder and store a request. `host_decides` emits `succession_requested` and calls `set_host_decides`. `election` emits `election_needed` and calls `WyrdElectionAdapter.start_election`. The role stays `contested` until `assign`. `none` does not pick. A successor is never the departed holder. The successor emits `role_holder_changed` and records `role_changed` with the role id as a tag. No successor emits `role_vacant`.

`vacancy: abolish` runs only after a strategy finds nobody. An open contest has not failed yet, so it does not abolish. Abolish clears the holder for good, records `role_abolished` (actor is the departed holder, target is the role id), and later `assign` calls fail until `define` or a new game. `start_new_game` pushes `WyrdRoles: host_decides has no callback` when a role uses that strategy and neither the callback nor `succession_requested` is connected. It pushes `WyrdRoles: election has no adapter` when a role uses `election` and neither a `WyrdElectionAdapter` nor `election_needed` is connected.

Each succession step writes one `succession` trace line (`role`, `strategy`, `from`, `to`, `reason`) when tracing is on. `WyrdTrace.prefix` keeps the line when the role starts with that text. Reasons are `picked`, `none`, `contested`, `assigned`, and `abolished`. Contest requests and abolished role ids are saved on the roles blob. Schema version stays 1. A saved status `pending` loads as `contested`.

Slot modes:

- `live` is the current holder.
- `locked_at` freezes in `enter_stage` for that stage and stays frozen. If that frozen holder is vacated or is not alive, the slot state is `locked_gone` even when the role has a successor. `holder()` stays the frozen person.
- `cast` picks once in `begin_quest` from `WyrdWorldAdapter.candidates`. The condition is tested with `candidate` bound to each id. A seeded pick is frozen with status `default`. No survivor leaves the slot `empty`. A later `begin_quest` does not pick again. One `cast` trace line (`quest`, `role`, `slot`, `entity`, `reason`) is written when tracing is on. Reasons are `picked` and `empty`. `WyrdTrace.prefix` filters it the same way as a slot line.

A cast slot or param compiles a cast plan from the top-level `and` clauses: scope (no `candidate`), at most one pin (`candidate == …`), local world clauses (`has_tag`, `alive`, `kind`, `display_name`), and everything else as rest. When `cast_index_enabled` is on (the default), the world adapter's `reports_changes()` is true, and the plan is not a full scan, the cast reuses that adapter's `candidates` answer and the cached local results until `Wyrd.invalidate_world(ids)`. An empty id list drops the cache. A host that does not report changes, a `chance` condition, and a plan marked scan still walk every answer. Role assignment does not clear the cache; a pin or a rest clause reads roles on each call.

Slot-state precedence is `locked_gone`, `contested`, `empty`, then `barred`, `hostile`, `unwilling`, `successor`, and `default`. The first state that applies and has a declared variant on the current stage wins, except `contested`: with no `contested` variant the `empty` variant is used and the state stays `contested` (reason `fallback_empty`). `locked_gone` still beats a contest. `hostile` is `disposition(holder, player)` below `hostile_threshold` (20, or the role override). `unwilling` evaluates its condition with `$h` bound to the holder. `barred` evaluates its condition against the player. A quest resolution writes one `slot_state` trace line (`quest`, `role`, `slot`, `state`, `reason`). Set `WyrdTrace.prefix` to keep lines whose quest, role, or slot starts with that text. The same state and reason are not logged again until they change. A `contested` variant does not satisfy the empty coverage warning.

A secret role's holder is in `known/<agent>` under `role.<id>.holder` only after `tell`. A public holder is visible to `known` without a write. `holder()` still returns the mechanical holder.

`render_table(prefix)` prints one sorted row per role. Columns are `role`, `holder`, `status`, `strategy`, `flags` (`pending`, `abolished`, or `-`), and `frozen` (`quest/slot=holder:status`, comma-separated). An empty holder is `-`. `prefix` keeps role ids that start with that text. `wyrd roles --manifest <path> [--prefix text] [--save path]` boots a runtime, optionally loads a JSON save, and prints that table. The headless entry is the CLI. The M7 inspector is later.
