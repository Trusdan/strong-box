# generator

`Wyrd.generator.offer(source, key, tier, payload)` queues unsaved story pressure. The queue is a FIFO. The same source and key replace tier and payload in place and keep their position. An empty source or key, a tier that is not in `WyrdConfig.pressure_tiers`, or a payload value other than string, number, or bool is rejected. An empty tier list makes every named tier unknown. An empty tier is always accepted.

`pressure_tiers` is an ordered list, lowest first. `tier_rank` is the index, or -1. `tier_matches` is true for an empty offer tier and for a template with no `tier:`. Otherwise the offer's rank must sit between the template's low and high, inclusive. A single name is that name at both ends. Unknown names do not match a tiered template.

A template `on_deed <verb> [where <condition>]` queues an offer when a matching deed is recorded. The key is `<template>:<deed id>`, the source and origin are `deed`, and the tier is empty. The same key replaces. A deed restored by `load_state` does not queue an offer. The queue is cleared by `start_new_game`, `load_content`, and `load_state`. It is not part of the save.

With tracing on, a queued or replaced offer logs `wyrd gen_offer source=… key=… tier=… origin=host|deed template=… queued=<n> replaced=true|false`. A rejected offer does not. Load does not log the line. Replay skips it.

The scheduler's `generate` queue has share 0. One unit calls `take_next` and then `generate_handler`. The runtime installs that handler. It picks a template, casts `mode: cast` slots, and binds params, then reserves the instance number. `_game_tick` accepts those proposals after `quests.on_tick` and `dialogue.on_tick`. The instance is created at the end of tick T. Its waits are first checked on tick T+1.

`propose(context)` does the same pick, cast, and bind without queueing. `context` is `{source, key, tier?, payload?}`, validated like `offer`. It returns null when the input is rejected or nothing can be proposed. `accept(proposal)` returns the instance id, or `stale`, `unknown`, or `accepted`. A second host propose of the same template is `stale` once the first accept moves the counter. Proposals are `p1`, `p2`, … and the sequence resets on a new game and on load. They are not saved. The payload is not readable by content.

Eligible templates are those whose id matches the offer's template when that is set, whose tier matches, whose `when` is true, whose live plus reserved count is below `max_active`, and whose weight is above 0. The top band shares the best priority and then the best specificity. The pick is `WyrdRng.for_decision(seed, "generator", "pick:<source>:<key>", now)` over that band in id order. Nothing eligible logs `gen_pick` with `reason=no_template` and does not roll. Weight 0 is never eligible. A failed cast or bind logs `reason=no_candidate` and does not move the counter.

Casts use the `generator` stream and key `cast:<instance>.<slot>`. The hand-written cast stream and `<quest>|<slot>` key are unchanged. A later cast condition sees earlier picks through a provisional scope. Params use key `param:<instance>.<name>`. An item snapshot adds `owner`. An item or object snapshot adds `place` when a spatial adapter is registered.

With tracing on, a decision logs `gen_tier`, `gen_pick`, `gen_candidates`, `gen_cast`, and `gen_bind`. A host propose also logs `gen_propose`. Accept calls `create_instance` first, so the order is `cast … reason=given`, `gen_create`, quest start, then `gen_accept`. A background unit does not log `gen_propose`. `gen_offer` records gain `payload`; the printed line is unchanged. Replay drives host `gen_offer`, `gen_propose`, and host `gen_accept`. A `gen_accept` with `origin` `queue` is the runtime's own accept during `tick` and is regenerated, not replayed. Deed-origin offers are skipped and regenerated by the replayed deed. The other `gen_*` rows are regenerated and compared by `diff`. Load logs none of them.

After a bind, and before anything is reserved or created, the proposal passes the hard validators in this order: `exists`, `place`, `protected`, `bounds`, then each `assumes:` part (`assumes`, then `known`). The first failure rejects the whole proposal and logs `gen_reject`. `exists` is skipped when no world adapter is registered. `protected` rejects `is_protected` unless the template sets `allow_protected: true`. `bounds` rejects `in_bounds(id, pack_id)` false. `assumes` is that part false in the world. `known` is a fact key the player knows at a different value than the world. Those two are evaluated while the provisional instance scope is still pushed, with `eval_bool`, so the part sees this proposal's casts and not another instance's. `eval_storylet` pushes an empty scope and is not used here.

`place` stays in that order and rejects nothing. An empty `place_of` means the host is not tracking that entity, so it passes, logs no `gen_reject`, and adds no retry key. The only case the rule would reject is a carried item whose owner has an empty place while the host tracks that owner. The spatial adapter returns an empty id both when a place was never stored and when it was stored empty, so those two cannot be told apart. The step therefore adds nothing beyond `exists`.

A rejection tries the next candidate set, up to `generator_retries` (default 8; a negative value is 0). Attempt 0 keeps the keys above. Attempt `r` >= 1 appends `:<r>` to the pick, cast, and param keys. An id rejected by `exists`, `place`, `protected`, or `bounds` is removed from later cast and param pools after the raw list is hashed for `gen_candidates`. `assumes` and `known` exclude nothing. `no_template` and `no_candidate` end the decision. When nothing is proposed, the host reason is `rejected` if any `gen_reject` was logged, and otherwise the same `no_template` or `no_candidate` as before. Nothing is reserved and the counter stays put. Each attempt opens and closes its own provisional scope.

`max_active` is unchanged. When it excludes a template that already passed tier, weight, and `when`, the decision logs `gen_cap template=<t> active=<live> reserved=<r> max=<max_active>` before `gen_tier`. An uncapped decision logs none.

`why_not(template)` reports the last decision that considered that template: `filtered` (with `tier`, `weight`, `when`, or `cap`), `not_picked`, `no_candidate` (the slot or param name), `rejected` (the rule list), `proposed`, or `created`. An unknown id is `missing`. A known template with no decision yet has an empty reason. The record is not saved and `clear` drops it. It adds no trace line.

An optional template `expires: <duration>` (minutes greater than 0; a bad value is `E_TEMPLATE_SYNTAX`) abandons an available or active instance once `now - created` reaches that duration. `created` is the creation minute. The generator block writes it only when the template expires, and a missing value on load becomes the load minute. Save schema stays 4. Expiry runs in `_game_tick` after the scheduler and before `quests.on_tick`. An open scene of that instance waits until a later tick. Any other open scene stays open: expiry does not call `abandon`. The line is `gen_expire instance=<id> reason=timeout`. The journal and the counter stay.

## Gullhaven examples

`example/content/gullhaven/harbor_templates.wyrd` holds the seven example templates: deliver a net, recover a stolen catch, investigate a cut mooring, escort a visitor, and a three-tier stew favor. `tests/scenario/test_m9_exit.gd` validates them, plays every route, saves mid-generation, and replays those routes.
