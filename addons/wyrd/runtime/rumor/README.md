# rumor

Precise-mode rumors. A host registers a `WyrdRumorPolicy`. There is no `.wyrd` syntax for one in this slice.

A deed starts a rumor only when it has a reveal claim and the first registered policy matches its verb. An empty verb list matches every verb. A policy with no kinds, or `max_hops` below 1, matches and does not spread. Later policies are not tried. `pass_chance` is clamped to 0..1. `1` always offers the hop. `0` never does. The registered copy is what runs. Policies are host registrations and are not saved.

Origins are the actor and the deed's witnesses, sorted. That witness list is the same slice the witness index stores. Spread does not scan the log. From each origin, in sorted order, one hop is queued to each sorted neighbor of the policy's relationship kinds (`WyrdSocial.targets`). A listener is queued once. The earliest speaker is the one who offers it. A later speaker does not get a second unit.

One scheduler unit is one token: `deed`, speaker, listener, hop, separated by tabs. Hop 1 is the first step away from an origin. The unit rolls `WyrdRng.for_decision` with stream `rumor`, that token as the decision key, and the hour bucket of the current minute. Adoption uses `credibility_score(listener, speaker)` and `credibility_threshold`. The default score is disposition, which reads the social cache. An accepted hop writes `believed/<listener>` only. It does not write `known:` or `world:`. That write also notes the listener on the deed log's believer index, at the current minute. A drop does not. The index is saved with the deed row. See `runtime/deeds/README.md` and `runtime/save/README.md`. A rejected hop, or a hop the roll skips, does not write and does not continue. The next hop is queued only after a write, and only while the hop number is below `max_hops`.

`WyrdSpatialAdapter.precision(place)` answers `precise` or `coarse`. The default is `precise` and does not `push_error`. An empty place counts as precise. A listener standing in a coarse place consumes the precise unit, does not adopt, and does not pass the claim on. That hop does not open a reach row.

A deed whose own place is coarse does not queue hops. It stores one reach row for `(deed, place)` at level 0. The row keeps the claim, the policy id, and the minute it was born. `WyrdConfig.rumor_coarse_minutes` (default 60, one game hour) is the cadence. `0` or a negative value disables rises. When the scheduler visits the place it reads `precision` again. Each crossed clock boundary (`floor(now / coarse) - floor(born / coarse)`) enqueues one rumor token, `reach`, deed, place, and the level that token will reach, separated by tabs. Those tokens share the rumor queue and its work budget. A token already queued still raises the level if the place later becomes precise. New tokens stop. Rows enqueue in sorted key order.

`belief` and `believes` call `materialize` before the belief cache when a reach row exists. An empty reach list returns the hot cache first. The NPC's current place must still be that coarse place. There is no occupant list and no new host method. The lowest numeric deed id for that place and fact, with level at least 1 and no earlier draw for that NPC, is the one rolled. Level 0 does not roll and does not log. Chance is `level / WyrdRumor.REACH_FULL` clamped to 0..1. `REACH_FULL` is 4, so four coarse ticks are certain (`randf` is below 1). The stream is `rumor`. The decision key is `materialize`, deed, place, NPC, level. The time bucket is the same hour bucket as a hop. An accept writes `believed/<listener>` only and notes the same believer index, at the minute of the ask. A reject is stored too, so a later rise does not roll that pair again. A second deed can roll on a later ask when the first did not write. An existing `believed/` value is left alone. `known:` and `world:` stay unchanged.

`mutations` is an array of `{field, to, keep_chance_fn}` on the policy. There is still no `.wyrd` syntax. `field` is the claim fact key. A different field is skipped and does not log. `keep_chance_fn(value, hop)` returns a chance in 0..1. A function of no arguments, or of the value only, is called with what it declares. The roll is `WyrdRng.for_decision` on stream `rumor`. The decision key is `mutate`, deed, speaker, listener, hop, field, and the mutation's index in the array. The time bucket is the hour bucket. `randf() < chance` keeps the value. Otherwise `to` runs. `to(value, hop)` returns the replacement. The string `drop` removes the field. A missing callable keeps the value and reports `push_error`.

Mutations run only after the hop is offered and credibility accepts. A coarse listener does not mutate. Each mutation logs one line. The listener's copy is what the next hop offers, so a later listener does not hear the original claim. A drop does not write `believed/<listener>` and does not continue. The deed row is not edited.

A materialize that accepts evaluates the same list once. The hop number is the reach level. The speaker in the decision key and on the trace line is the place. A drop leaves no belief. The draw is still once.

The claim table, the seen set, the queued set, reach rows, pending counts, the once-set, the per-listener mutated copies, and the rumor tokens are saved in `flight`. Mutation callables are not. Load rebinds them from the registered policy with that id, so register policies before `load_state`. A job or reach row whose policy id is not registered is `error[E_SAVE_POLICY]` and `push_error`, naming the policy id and the deed. That deed's jobs, tokens, reach rows, and copies are left out. Other rumors load. Beliefs already written stay. The load still applies. A schema 2 save has no `flight` key and loads with an empty queue. Load does not log a rumor line. Beliefs already written stay in the fact store, including a value a mutation already stored. Deed compaction does not cancel an in-flight claim and does not start a new one.

With tracing on, a hop logs `wyrd rumor hop deed=%s policy=%s from=%s to=%s hop=%d key=%s taken=%s reason=%s`. `reason` is `pass`, `chance`, or `coarse`. An offered hop then logs `wyrd rumor adopt listener=%s speaker=%s policy=%s key=%s score=%s accepted=%s`. `who` is the listener. `speaker` is the person who offered it. `path` is the policy id. A rise logs `wyrd rumor reach deed=%s place=%s policy=%s level=%d key=%s`. `who` on that line is the place, because a rise has no NPC. A draw logs `wyrd rumor materialize listener=%s place=%s policy=%s key=%s level=%d chance=%s accepted=%s`. A mutation logs `wyrd rumor mutate listener=%s speaker=%s policy=%s field=%s hop=%d kept=%s result=%s value=%s`. `result` is `keep`, `mutate`, or `drop`. `who` is the listener. `path` is the policy id on every rumor line. Replay skips all five. Load does not log them.
