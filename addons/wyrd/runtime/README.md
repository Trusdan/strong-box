# runtime

Engine code with no editor dependency. `wyrd_runtime.gd` is the instanceable runtime. `wyrd.gd` is the facade over one runtime. Tests construct a `WyrdRuntime` directly. The plugin does not register the autoload.

## Load

`load_content(manifest)` compiles the manifest's `.wyrd` sources with `WyrdPack.compile` and, when that reports no errors, builds a runtime-only `WyrdContent` (quests, scenes, storylets, sequences, lines, condition table, dependency index, `manifest_hash`). Storylet conditions are not added to the tick queue. `director.query(scope_kind, scope_id, speaker)` filters by scope, speaker, secrecy, `when`, and cooldown, then ranks. Secrecy names are `WyrdConfig.secrecy_tiers`, lowest first. The unlocked name is the world fact `WyrdConfig.secrecy_fact`. A name above that unlock is dropped before ranking, and one `secrecy` line is logged when tracing is on. When `WyrdConfig.trace_director` is true, each scope-and-speaker match also logs one `director_candidate` line. Load does not log it. `speaker: any` is a wildcard. A win records `seen` and `last_minute` in the schema 2 `storylets` bag and then draws the body. A bark may also cool a concrete speaker through `speaker_cooldown`, saved as `bark_speakers`, and a bark win emits `bark_ready`. A spatial `waits_until` is rechecked when one of that stage's `on` events is emitted, not on later ticks. `director.why_not` explains one storylet for a scope and speaker and does not record a selection. A locked secrecy name is reason `secrecy`, and the line includes `tier` and `unlocked`. `wyrd why-not` prints that line. `storylets.draw` does not record a selection. An unknown storylet id in that bag is kept and ignored. Any compile error refuses the load and leaves the runtime empty. Warnings do not refuse it. `export-json` stays a debug format.

Exported games must include `*.wyrd` and the manifest in the export filter. Wyrd has no import plugin.

## Facade

`configure`, `register_adapter`, `register_function`, `register_disposition_formula`, `register_group_precedence`, `register_credibility`, `register_rumor_policy`, `invalidate_groups`, `start_new_game`, `load_content`, and `tick` forward to the runtime. `register_disposition_formula` forwards to `social.register_formula`. Sub-objects:

- `facts` — `set(key, value)` and `get(key)` for the world perspective, `set_in` / `get_in` for `known/<agent>`, `believed/<agent>`, and `held/<group>`, `clear_in` for a believed or held key, `invalidate(prefix)`, `subscribe(prefix)`, signal `fact_changed(key, old_value, new_value)`. Godot's `Object.set` and `Object.get` already own those names, so the store implements them with `_set` and `_get`. A perspective argument cannot be added, and `set` cannot return a bool. `choice_summary` reads `set` and `inc` provenance and can filter by scene, choice, key prefix, and time. `wyrd choices` prints it. `recap: true` keeps that provenance when deeds compact.
- `events` — `emit(name, payload)`, `begin_batch`, and `end_batch`. The payload is checked against the pack's `events` block. A bad payload is `push_error`, a trace row `emit_rejected`, and no cache drop. A good emit drops `on_event` caches, including every concrete key of a pattern, re-checks only the dirty dependents in index order, and returns after that re-check. `begin_batch` / `end_batch` run handlers on each emit and re-check once on the outermost `end_batch`. An open scene is not aborted. `waits_until` and `start when` wake from the re-check. A stage `on` handler runs at most once per emit and does not cascade into the next stage. The last 32 emits sit in a ring buffer for `debug_dump`. They are not saved. See `docs/language.md#events`.
- `deeds` — `record(...)`. Decay, `deed_count`, and `deed_score` read the log.
- `social` — baselines, kinds, `axis`, `disposition`, and an optional formula.
- `rumors` — precise hops, coarse reach, and per-hop mutations for a registered `WyrdRumorPolicy`. One unit offers one deed to one listener, or raises one reach level. A heard rumor writes the mutated copy to `believed/<listener>` only. See `runtime/rumor/README.md`.
- `publish` — periodic document issues. One unit freezes one issue. `deeds_known_to(group, since, filter)` reads the witness index and the rumor believer index. See `runtime/publish/README.md`.
- `documents` — readable documents. `open`, `create_copy`, `has_read`, and `has_copy`. Signal `document_read`. Read flags are `(reader, document)` pairs kept here and saved in the `documents` bag. They are not stored facts. `Wyrd.facts`, the fact schema, the `W_FACT_*` lints, the facts export, and the snapshot `facts` section do not see them. `has_read(reader, doc)` is the query. Design §2.17 describes a stored fact `read:<reader>:<doc_id>`; this runtime does not write that fact. See `runtime/save/README.md` and `runtime/trace/README.md`.
- `roles` — `assign`, `vacate`, `define`, `tell`, `begin_quest`, `enter_stage`, `holder`, and `slot_state`.
- `quests` — status, stage, outcome, journal, `abandon`, `request_host_step`, `complete_host_step`, `register_date_formatter`. Signals: `quest_state_changed`, `stage_changed`, `journal_entry_added`, `content_unavailable`, `host_step_requested`.
- `dialogue` — `open_scene`, `advance`, `choose`, `abort`, `register_line_audio`, `can_save`. Signals: `line_ready`, `choices_ready`, `scene_started`, `scene_ended`. `scene_started` fires after a scene opens and before its first `line_ready`.
- `debug` — `snapshot(sections, prefix, offset, limit)` reads live facts, roles, quests, the dirty queue, deeds, social axes, group precedence, and provenance. The document is not saved. One `debug_snapshot` line is logged when tracing is on. See `runtime/debug/README.md`.
- `coverage` — hit counts for storylets, slot variants, and line ids. Recording is off until `enabled` is set. Counts are not saved. `merge` adds them to `user://wyrd_coverage.json`. `wyrd coverage` lists the ids that were never hit. See `runtime/debug/README.md`.
- console — `WyrdConsole` in `runtime/console`, not a facade member. `wyrd console` runs the §3.3 commands. A release export excludes `addons/wyrd/runtime/console/*`. See `runtime/console/README.md`.

`save_state()` returns a JSON-safe dictionary. `load_state(data)` returns a `WyrdLoadReport` (`ok`, `diagnostics`, `manifest_hash`, `rows`) and emits `load_report_ready` once. `rows` lists `refused`, `manifest`, `template`, `ai`, `policy`, `kept`, `alias`, and `missing_stage`. A refused or wrong-typed save is rejected before anything is imported. Both `save_state` and `load_state` refuse while a scene is open (`E_SAVE_OPEN`). `rng_stream(name)` returns a named PCG32 stream seeded from the game seed. `draw_u32(name)` draws from that stream. `trace` is a `WyrdTrace`; turn `enabled` on to record. `start_new_game` clears streams and the trace log. It does not write a save.

`believed/<agent>` and `held/<group>` store schema facts. A write there does not change `world` or `known`. `knows` reads a role reveal or `known/<agent>`. The condition `known` was removed; compiling it reports `E_KNOWN_REMOVED`. `believes` is truthy of the agent's own belief, then `held` of `groups_of` in precedence order. An explicit false stops that walk. There is no fallback to `known` or `world`. `belief` and `believes(...) == v` read the value. `held(group, key)` reads that group only. `register_group_precedence` replaces the list order. Membership is cached until `invalidate_groups` or an emit of `groups_changed`, which also marks the synthetic read `group.membership`. A belief change logs one `belief` line when the value changes. A lookup logs one `belief_lookup` line. `conflicted(agent, key)` is true when two member groups hold different present values. The agent's own belief is not a position. One `conflict` line is logged per resolution. `learn` and `forget` write `known/<agent>`. A deed witness stores `saw`, `heard`, or `inferred`. `saw` learns a revealed fact. `heard` and `inferred` believe it. One `knowledge` line is logged per knowledge change, and one `perception` line per witness. Those lines are filterable by agent or key. A `statement: true` deed keeps those modes and does not write from them. Each witness is judged with `credibility_score(listener, speaker)`, which defaults to `disposition(listener, speaker) / 100`. `register_credibility` replaces that score and is not saved. The listener accepts when the score is at least `credibility_threshold` (default 0.5). Acceptance writes `believed/<listener>` only. One `credibility` line is logged per listener, including a rejection. A kind the observer holds toward the subject multiplies that axis's deed delta. `reputation(subject, group)` is the mean disposition of the group's members toward the subject, excluding the subject. It is derived from members, kinds, baselines, and deeds. One `reputation` line is logged per call. `deeds.compact` merges same-minute rows and drops rounded-off weight. Scores stay within that rounding, and `perceived` keeps its latest mode. `compact_after` of 0 does not compact on tick. One `compact` line is logged per call. A registered rumor policy offers a deed's reveal claim along relationship kinds, one listener per rumor unit. Adoption writes `believed/<listener>` only. A coarse place does not spread. The in-flight claim table is not saved. Schema stays 2. Load drops it and does not log `rumor_hop` or `rumor_adopt`.

## Text

Dialogue text is always shown, whether or not a line is voiced. `line_audio` may return null. Audio never hides a line and never advances it. `advance()` is the only way on. A `{holder(name)|variants}` span picks a variant line for the current holder, or the name-free line. That pick logs one `voice` line when tracing is on and is not saved. A journal stores the chosen text and line id.

## Quests

`requires` naming a pack other than the loaded pack sets `unavailable` and emits `content_unavailable` when content loads and again on `start_new_game`. `start when` and `waits_until` move only after the tick queue has re-checked them. A stage that names a scene offers it. The host calls `open_scene`. Transitions wait until that scene ends normally. An aborted scene stays offered.

The quest completes when every declared outcome is set and the current body has no transition left. Any outcome value `failed` fails the quest. A stage `region` runs beside its siblings. The active leaf of each region is saved on that quest and omitted when empty. A `sequence` counts matching events in game minutes. `progress(id)` and `done(id)` read it. Partial progress is saved under `sequences` on schema 2 and omitted when nothing has started.

Journal text is interpolated once and stored with the game time. The default date is `day N, HH:MM` (day 1 at minute 0, 1440 minutes per day). `register_date_formatter` replaces that for later writes. A stored date does not change.

`await_host <screen> returns { field, ... }` is a stage statement (`docs/language.md#host-modal-step`). It pauses the remaining entry steps. `complete_host_step` resumes them. A waiting host step is part of the save.

## Save

`runtime/save` writes schema version 1: content pack id and manifest hash, facts, deeds, social baselines and kinds, roles, quests (including frozen journal text), effect provenance, game minutes, the game seed, and every named RNG stream. 64-bit integers are 16 hex digits. The migration table is empty. A manifest hash that does not match warns in a debug build and is silent in a release. The inspector snapshot is not a save key. See `runtime/save/README.md`, `runtime/debug/README.md`, and `runtime/trace/README.md`.
