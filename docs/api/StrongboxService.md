# StrongboxService

Generated by `tools/gen_api_docs.sh` from the `##` doc comments. Do not edit by hand.

**Experimental:** this API may change before 1.0.

Inherits: `Node`

One place for a game to save and load: slots, the world store, migrations and playtime.

Use it as an autoload (for example named `Strongbox`). The game owns scene changes: set `scene_changer` to a function that loads a scene by key and returns its root once it is ready. `save()` returns at once; `load()` is a coroutine, so call it with `await`. Both return a [StrongboxResult](StrongboxResult.md); every error code has a short message in `MESSAGES`.
Signals fire in this order: `save_started` then `save_finished` (also on a failed write); `load_started` then either `load_finished` or `load_failed`. A call refused at once (busy, or a guard says no) emits nothing.

## Signals

### `save_started`

```gdscript
signal save_started(slot_id: String)
```

Emitted when a save begins, after the busy check and the guards.

### `save_finished`

```gdscript
signal save_finished(slot_id: String, result: StrongboxResult)
```

Emitted when a save ends, with its result (check `StrongboxResult.ok`).

### `load_started`

```gdscript
signal load_started(slot_id: String)
```

Emitted when a load begins, after the busy check.

### `load_finished`

```gdscript
signal load_finished(slot_id: String, result: StrongboxResult)
```

Emitted when a load succeeded.

### `load_failed`

```gdscript
signal load_failed(slot_id: String, code: StringName, message: String)
```

Emitted when a load failed. Before the live step the running game is untouched.

## Methods

### `message_for`

```gdscript
static func message_for(code: StringName) -> String
```

Returns the short message for `code`, or an empty string for an unknown code.

### `add_save_guard`

```gdscript
func add_save_guard(guard_name: StringName, guard: Callable) -> void
```

Adds a save guard. `guard` takes no arguments and returns an empty String to allow saving, or a reason to refuse. A guard with the same name is replaced.

### `remove_save_guard`

```gdscript
func remove_save_guard(guard_name: StringName) -> void
```

Removes a save guard.

### `can_save`

```gdscript
func can_save() -> Dictionary
```

Asks every guard. Returns `{"ok": bool, "reasons": Array`String`}`.

### `register_provider`

```gdscript
func register_provider(provider_name: StringName, capture: Callable, restore: Callable, priority: int = 0, validate: Callable = Callable()) -> StrongboxResult
```

Registers a global provider on `world` (see `StrongboxWorldStore.register_provider()`), with an optional `validate` `(data: Dictionary) -> String`. On load each validator checks its provider's data before anything live changes; a non-empty String refuses the load.

### `save`

```gdscript
func save(slot_id: String, label: Dictionary = {}) -> StrongboxResult
```

Saves the current scene, the world store and globals to `slot_id`. `label` holds load-menu labels (see `StrongboxSlots.write()`). On failure the world store is unchanged. On success `StrongboxResult.value` is the slot's metadata.

### `load`

```gdscript
func load(slot_id: String) -> StrongboxResult
```

Loads `slot_id`: reads it (falling back to a backup), upgrades it, validates all of it, and only then replaces the world store, changes to the saved scene through `scene_changer`, restores globals and restores the scene. If anything fails before that, the running game is untouched. On success `StrongboxResult.value` is `{"source", "failures", "migrated", "scene_key", "restore", "providers"}`; `source` is `"main"` or the backup used, `failures` lists the files skipped, and `providers` holds what successful provider restores returned. A provider restore that returns a failed [StrongboxResult](StrongboxResult.md) fails the load with that result.

### `new_game`

```gdscript
func new_game() -> StrongboxResult
```

Starts a new game: clears the world store (scenes, spawned nodes, tombstones, globals) and playtime. Providers, guards and the spawn allow-list stay. Refused while busy.
